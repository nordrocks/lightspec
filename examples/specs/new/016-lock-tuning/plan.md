# 016-lock-tuning: план

## Техническое решение

- порог попыток — настройка аккаунта в основной базе
- кэш сессий убирается: adr:no-cache

## Задачи

### [x] Задача 001: Настраиваемый порог блокировки
Реализует: req:AUTH-003, req:AUTH-010
Документация: doc:auth/login
Проверка: тесты сценариев req:AUTH-003, req:AUTH-010

- Действие: порог из настроек
  - Что: аккаунт блокируется после заданного администратором числа попыток
  - Как: порог читается из настроек аккаунта, по умолчанию — пять
  - Уровень: локальное
    - меняется только проверка входа
  - Файлы:
    - MOD `src/auth/lockout.py`

### [ ] Задача 002: Проверка сессий без кэша
Реализует: req:AUTH-003
Документация: doc:auth/login
Проверка: тесты сценариев req:AUTH-003

- Действие: убрать кэш сессий
  - Что: сессия проверяется по базе
  - Как: обращения к Redis заменяются запросом к таблице сессий
  - Уровень: архитектурное
    - уходит хранилище: adr:no-cache
  - Файлы:
    - MOD `src/auth/sessions.py`
    - DEL `src/cache/redis.py`
