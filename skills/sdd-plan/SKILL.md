# sdd-plan

Результат — `plan` с задачами, файлы `delta/` документации, `adr` фичи в `delta/_project/adr/`. `spec` — в `planned`.

Пути — от папки скилов, родительской для папки этого скила. Команды — по «Командам» в `rules.md`. Прочитай `rules.md`.

## Запуск

| Аргумент | Что делать |
|---|---|
| `<номер>` или `<ID фичи>` | планировать эту `feature` |
| нет | `spec` в `approved`, `planned` или `implementing` |

| Статус `spec` | Что делать |
|---|---|
| `approved` | напиши `plan` по шагам. `plan` уже есть — сверь его с изменённой `spec` и поправь по «Правке» в `formats/plan.md` |
| `planned`, `implementing` | правка утверждённого `plan` |

## Шаги

### 1. План реализации

1. Прочитай для плана:
   - `spec`: Границы и Решения
   - файлы `delta/` требований и контрактов
   - `requirements` и `contracts`, которых касается `delta`
   - `architecture`, `conventions`, `project-doc`, действующие `adr`
   - `code` по теме
2. Техническое решение — ключевые решения реализации. Решение — ADR по `formats/adr.md`: запиши `adr` фичи в `delta/_project/adr/<ID ADR>.md` и сошлись на него: adr:<ID ADR>. Меняет действующий ADR — по «Замене» в `formats/adr.md`.
3. Задачи — по `formats/plan.md`.

Дыра или противоречие в `spec` — не планируй в обход. Запиши вопрос в Открытые вопросы `plan` и остановись. Следующий шаг — `sdd-spec`.

### 2. Документация

1. Прочитай для документации:
   - `domain-docs` поддоменов, которых касается `delta`
   - `architecture`, `conventions` и `project-doc`
2. Напиши файлы `delta/` для `domain-docs`, `architecture`, `conventions` и `project-doc`. Пройди части `delta/` требований и контрактов и Техническое решение. Строки «`delta` контрактов» выполняют «Обязательные связи» в `rules.md`:

| Откуда | Изменение | Что сделать в `delta/` документации |
|---|---|---|
| `delta` требований | ADDED или MODIFIED | MODIFIED блоков `domain-docs` поддомена, которые описывают это поведение. Такого блока нет — ADDED нового блока. Устройство не меняется — документацию не трогай |
| `delta` требований | MODIFIED с другим файлом — перенос в другой поддомен | MODIFIED блоков обоих поддоменов, которые описывают это поведение |
| `delta` требований | REMOVED | MODIFIED блоков, которые описывают это поведение: убери его. Блок опустел — REMOVED блока |
| `delta` требований | ADDED шапки нового файла | ADDED шапки и блоков нового файла `domain-docs` |
| `delta` требований | REMOVED шапки файла | REMOVED шапки и всех блоков его `domain-docs` |
| `delta` контрактов | ADDED | MODIFIED блока, который объясняет сценарий с этим элементом в `Контракты:`: добавь элемент в `Контракты:` |
| `delta` контрактов | MODIFIED | MODIFIED блоков с этим элементом в `Контракты:`: текст под новое поведение |
| `delta` контрактов | REMOVED | MODIFIED блоков с этим элементом: убери его из `Контракты:` и текста |
| Техническое решение | меняется устройство системы | ADDED или MODIFIED блоков `architecture` |
| Техническое решение | новая конвенция кода | ADDED или MODIFIED блоков `conventions` |
| Техническое решение | меняется тема `project-doc`: сборка, деплой, окружения | ADDED или MODIFIED блоков её `project-doc`. Новый `project-doc` — по «Сущностям» в `rules.md` |

3. Впиши каждый файл документации из `delta/` в `Документацию:` задач, которые делают описанное, — по «Задаче» в `formats/plan.md`.

### 3. Проверка и подтверждение

1. Проверь условия перехода в `planned`: `check-plan`. Нарушения в `plan` или `delta/` — исправь и проверь снова. Предупреждения о документации поддомена — покажи пользователю и реши с ним, нужна ли правка.
2. Выведи в чат Техническое решение, ADR и «Итог».
3. После явного «да» поставь в `spec` `Статус: planned`.

### Правка утверждённого `plan`

1. Выведи в чат «Итог» правки: что поменяется в задачах и в `delta/` документации.
2. После явного «да» внеси правку в `plan` по «Правке» в `formats/plan.md` и в `delta/`.
3. Проверь, как в шаге 3.1.

## Итог

Новый `plan` — строка на каждую задачу:

| Задача | Реализует | Документация | Файлы |
|---|---|---|---|
| <номер>: <название> | <ссылки из `Реализует:`> | <ссылки из `Документации:`> | <файлы `code` с пометками `ADD`, `MOD`, `DEL`> |

Правка `plan` — строка на каждую новую или изменённую задачу:

| Задача | Изменение | Что именно |
|---|---|---|
| <номер>: <название> | <новая или изменена> | <одной фразой> |

Что поменяется в документации — строка на каждую часть из списка «Части delta/» в выводе `check-plan`:

| Что меняется | Блок | Изменение |
|---|---|---|
| <одной фразой> | <имя блока> | <ADDED, MODIFIED или REMOVED> |

## В конце

Кроме статуса и следующего шага — новые `adr`.
