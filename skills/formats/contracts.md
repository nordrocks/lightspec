# Формат контрактов

Формат `contracts`: внешний интерфейс системы — операции, события, протоколы и модели данных, которые она предоставляет клиентам.
- `<интерфейс>` в шапке и в имени элемента — имя файла
- интерфейсы, транспорт и типы данных выбирает проект

## Структура

| Что | Заголовок | Свойство | Обязательно | Содержание |
|---|---|---|---|---|
| шапка | `# <интерфейс>: контракт` | — | да | потребители интерфейса и способ подключения: транспорт и представление данных для всего интерфейса |
| шапка | | `Источник:` | да | — |
| элемент | `## <ID элемента>` | — | да | одна фраза: назначение элемента. Затем разделы по «Элементу» |
| элемент | | `Источник:` | да | — |
| элемент | | `Тип:` | да | по «Элементу» |
| элемент | | `Вход:` | нет | модели входа операции. Вход — объединение их полей |
| элемент | | `Выход:` | нет | модели результата операции |
| элемент | | `Ошибки:` | нет | модели ошибок операции: общие и свои. Имя модели ошибки — её код |
| элемент | | `Данные:` | нет | модели данных события |
| Поля | `### Поля` | — | нет | таблица — по «Полям» |
| Шаги | `### Шаги` | — | нет | нумерованный список: вызов, событие или реакция на ошибку. Ветвление — только по ошибке или значению поля |
| Гарантии | `### Гарантии` | — | нет | список: идемпотентность, доставка, порядок |
| Формат | `### Формат` | — | нет | список: транспорт и представление элемента, если они уточняют шапку. Например, метод и путь вызова, топик и ключ события |

## Элемент

Свойства и разделы — по значению `Тип:`. `Источник:` и `Тип:` — у всех.

| `Тип:` | Свойства | Разделы |
|---|---|---|
| операция | `Вход:`, `Выход:`, `Ошибки:` | Гарантии, Формат |
| событие | `Данные:` | Гарантии, Формат |
| протокол | — | Шаги, Формат |
| модель | — | Поля, Формат |

## Пример

Операция, протокол и модель:

```markdown
# public-api: контракт
Источник: feature:007-login-lockout

Мобильное и веб-приложение. HTTPS, JSON, базовый URL `https://api.example.com/v1`.

## public-api.login
Источник: feature:007-login-lockout
Тип: операция
Выход: contract:public-api.session

Вход по логину и паролю.

### Гарантии

- идемпотентность: нет

### Формат

- вызов: `POST /login`

## public-api.refresh
Источник: feature:007-login-lockout
Тип: протокол

Продление сессии без повторного ввода пароля.

### Шаги

1. вызов с `token` вернул HTTP 401
2. клиент отправляет `refreshToken` на `POST /refresh` и получает новую contract:public-api.session
3. `POST /refresh` вернул HTTP 401 — клиент снова вызывает contract:public-api.login

## public-api.session
Источник: feature:007-login-lockout
Тип: модель

Открытая сессия пользователя.

### Поля

| Поле | Тип | Формат | Обязательно | Описание |
|---|---|---|---|---|
| token | string | JWT | да | для вызовов от имени пользователя |
| refreshToken | string | — | да | для contract:public-api.refresh |
```

Событие и его данные:

```markdown
# events: контракт
Источник: feature:007-login-lockout

Партнёрские сервисы. Kafka, JSON.

## events.account-locked
Источник: feature:007-login-lockout
Тип: событие
Данные: contract:events.account-locked-data

Аккаунт заблокирован после неудачных входов.

### Гарантии

- доставка: хотя бы один раз

### Формат

- топик `account-events`, ключ — `accountId`

## events.account-locked-data
Источник: feature:007-login-lockout
Тип: модель

Какой аккаунт заблокирован и до какого времени.

### Поля

| Поле | Тип | Формат | Обязательно | Описание |
|---|---|---|---|---|
| accountId | string | UUID | да | ID аккаунта |
| lockedUntil | datetime | ISO 8601, UTC: `2026-10-26T14:35:00Z` | да | время разблокировки |
```

## Поля

Таблица `| Поле | Тип | Формат | Обязательно | Описание |`, строка на поле:
- Поле — имя поля. Вложенное — через точку: `user.id`
- Тип — тип данных по правилам проекта: `string`, `integer`, `datetime`
- Формат — представление значения: шаблон, кодировка, единицы, пример. Тип однозначен — `—`
- Обязательно — `да` или `нет`
- Описание — что поле значит для клиента, ограничения
