# Формат дельты

Формат `delta`: изменения main, которые вносит фича, — части файлов main в формате их сущности со свойствами изменения.
- в файле — только изменённые части, в любом порядке
- часть — единица изменения. У ADR часть — файл целиком
- новый файл — шапка и все блоки с ADDED. Удаление файла — шапка и все блоки с REMOVED

## Структура

| Что | Заголовок | Свойство | Обязательно | Содержание |
|---|---|---|---|---|
| часть | как в формате сущности | — | нет | по «Свойствам изменения» |
| часть | | `Изменение:` | да | что фича делает с частью: `ADDED`, `MODIFIED` или `REMOVED` |
| часть | | `Источник:` | да | по «Свойствам изменения» |
| часть | | `Причина:` | да | по «Свойствам изменения» |
| часть | | свойства сущности | по формату сущности | по формату сущности, кроме `Источник:` |

## Пример

`delta/auth/login-requirements.md`:

```markdown
## AUTH-007: Разблокировка по ссылке из письма
Изменение: ADDED
Источник: None
Причина: None

<сценарии>

## AUTH-003: Блокировка после неудачных входов
Изменение: MODIFIED
Источник: feature:007-login-lockout
Причина: None

<полный новый текст требования>

## AUTH-002: Капча после неудачных входов
Изменение: REMOVED
Источник: feature:004-captcha
Причина: заменено req:AUTH-003
```

## Свойства изменения

| Изменение | `Источник:` | `Причина:` | Содержание |
|---|---|---|---|
| ADDED | `None` | `None` | вся часть, как ляжет в main |
| MODIFIED | `Источник:` части в main | `None` | вся новая часть, не diff |
| REMOVED | `Источник:` части в main | почему часть удаляется | ничего, кроме заголовка и свойств изменения |

- ADDED — части в main ещё нет
- не сошлось с main — конфликт: часть за это время изменила другая фича
- ADR — только ADDED. Замена — по «Замене» в `formats/adr.md`
- перенос требования в другой поддомен — MODIFIED в файле нового поддомена, ID тот же
