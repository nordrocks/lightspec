# Формат ADR

Формат `adr`: архитектурно значимое решение, которое дорого изменить, и его обоснование: контекст и последствия.
- одно решение — один файл
- `<ID ADR>` уникален в main

Решение — ADR, если верны оба признака:
- через год спросят «почему так?», а ответа нет ни в коде, ни в других сущностях
- переделка затронет много кода, данных или несколько доменов

Например, выбор хранилища, брокера или фреймворка, схема аутентификации, отказ от альтернативы, к которой будут возвращаться.

## Структура

| Что | Заголовок | Свойство | Обязательно | Содержание |
|---|---|---|---|---|
| шапка | `# <название решения>` | — | да | — |
| шапка | | `Источник:` | да | — |
| шапка | | `Заменяет:` | нет | только в `delta`: действующие ADR, которые этот заменяет |
| Контекст | `## Контекст` | — | да | проблема и ограничения, из-за которых нужно решение |
| Решение | `## Решение` | — | да | что решили — конкретно, одной-двумя фразами |
| Последствия | `## Последствия` | — | да | что меняется и чем платим: плюсы, минусы, новые ограничения |

## Пример

```markdown
# PostgreSQL как основное хранилище
Источник: feature:007-login-lockout

## Контекст

Нужны транзакционные блокировки строк для счётчика неудачных входов.
MySQL в текущей конфигурации их не даёт без смены движка таблиц.

## Решение

Основное хранилище — PostgreSQL 16.

## Последствия

- данные из MySQL переносятся миграцией
- блокировки строк — через `SELECT … FOR UPDATE`
- нужен новый сервис в инфраструктуре
```

## Замена

- действующий ADR не правится. Решение меняется — новый ADR с `Заменяет:` на старый
- что из старого решения остаётся в силе — повтори в новом
- новый ADR может взять `<ID ADR>` того, который заменяет
