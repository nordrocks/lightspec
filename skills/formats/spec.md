# Формат спеки

Формат `spec`: спецификация фичи — проблема, границы и изменения требований и контрактов, языком бизнеса.

## Структура

| Что | Заголовок | Свойство | Обязательно | Содержание |
|---|---|---|---|---|
| шапка | `# <ID фичи>: <название фичи>` | — | да | — |
| шапка | | `Статус:` | да | текущий статус — по «Статусам спеки» в `rules.md` |
| шапка | | `Основа:` | нет | фичи, на которые опирается эта |
| Контекст | `## Контекст` | — | да | что не так сейчас или что нужно получить. Кто от этого страдает и чем |
| Границы | `## Границы` | — | да | только разделы |
| Входит | `### Входит` | — | да | список — по «Границам» |
| Не входит | `### Не входит` | — | нет | список — по «Границам» |
| Решения | `## Решения` | — | нет | список — по «Решениям» |
| Открытые вопросы | `## Открытые вопросы` | — | нет | список вопросов к пользователю |

## Пример

```markdown
# 012-unlock-link: Разблокировка по ссылке из письма
Статус: draft
Основа: feature:007-login-lockout

## Контекст

Заблокированный пользователь не может войти, пока не закончится блокировка.
Он не знает, сколько ждать, и пишет в поддержку. Поддержка тратит время на типовые обращения.

## Границы

### Входит

- пользователь может разблокировать аккаунт по ссылке из письма о блокировке

### Не входит

- разблокировка через поддержку
- смена пароля по той же ссылке

## Решения

- ссылка действует 1 час. Причина: короче самой блокировки, иначе ссылка не нужна.

## Открытые вопросы

- нужна ли ссылка, если пользователь сам сменил пароль?
```

## Границы

- «Входит» — результаты, которые увидит пользователь или клиент
- «Не входит» — смежное, что легко принять за часть фичи
- пункт — результат, а не задача: «пользователь может разблокировать аккаунт», а не «добавить операцию»

## Решения

- пункт — `- <решение>. Причина: <почему>.`
