# Формат документов проекта

Формат `architecture`: устройство системы — компоненты, их связи, хранилища и интеграции.
Формат `conventions`: правила кода, общие для всего проекта.
Формат `project-doc`: одна тема, общая для всей системы, — например, сборка, деплой, окружения, наблюдаемость. Как устроено и почему так. Конфигурацию не копирует: она в `code`.

## Структура

| Что | Заголовок | Свойство | Обязательно | Содержание |
|---|---|---|---|---|
| шапка | `# <название>` | — | да | название: в `architecture` — «Архитектура», в `conventions` — «Конвенции», в `project-doc` — тема. Затем 1–2 строки: о системе, о коде в целом или о теме |
| шапка | | `Источник:` | да | — |
| блок | `## <название>` | — | нет | в `architecture` — устройство части системы, в `conventions` — одно правило кода, в `project-doc` — одна часть темы. Решение из ADR — со ссылкой `adr:<ID ADR>` |
| блок | | `Источник:` | да | — |

## Пример

```markdown
# Архитектура
Источник: feature:001-bootstrap

Монолит на Python: HTTP API для клиентов, события партнёрам через Kafka.

## Хранилище
Источник: feature:007-login-lockout

Основное хранилище — одна база для всех доменов: adr:postgres.
Счётчики и токены входа — в ней же, без кэша.
```

```markdown
# Конвенции
Источник: feature:001-bootstrap

Правила кода на Python для всего проекта.

## Время
Источник: feature:007-login-lockout

Время в коде и в базе — только UTC, тип с часовым поясом. Перевод в местное время — на клиенте.
```
