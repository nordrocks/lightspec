# sdd-apply

Результат — задачи `plan` выполнены в `code` и отмечены. Всё готово к `sdd-sync`.

Пути — от папки скилов, родительской для папки этого скила. Команды — по «Командам» в `rules.md`. Прочитай `rules.md`.

## Запуск

| Аргумент | Что делать |
|---|---|
| `<номер>` или `<ID фичи>` | реализовать эту `feature` |
| нет | `spec` в `planned` или `implementing` |

Начинай с первой невыполненной задачи.

## Шаги

1. `spec` в `planned` — поставь `Статус: implementing`.
2. Прочитай `spec`, `plan` и файлы `delta/`. Требования и контракты, которые реализуют задачи:
   - новые и изменённые — из файлов `delta/`
   - остальные — из main
3. Для каждой невыполненной задачи по порядку:
   1. сделай действия задачи — ровно их: файлы из `Файлы:`, устройство по `Как:`. Пункты «Не входит» из Границ `spec` не делай
   2. выполни «Проверку»: напиши и запусти тесты
   3. сверь `code` с `contracts`, которые реализует задача: модели входа, выхода и ошибок
   4. отметь задачу — по «Задаче» в `formats/plan.md`

   Задачу нельзя выполнить как написана — Открытые вопросы по `rules.md`.
4. Проверь всё, что пойдёт в main: `check-plan`. Нарушения — покажи пользователю, не исправляй. Следующий шаг:
   - нарушения в `plan` — `sdd-plan`
   - нарушения в `spec` — `sdd-spec`
5. Выведи в чат «Итог».

## Итог

Строка на каждую задачу, выполненную в этом запуске:

| Задача | Файлы | Проверка |
|---|---|---|
| <номер>: <название> | <файлы `code` с пометками `ADD`, `MOD`, `DEL`> | <какие тесты прошли> |

## В конце

Кроме статуса и следующего шага — невыполненные задачи, если остались.
