# Разбор файлов SDD

Как скрипты читают файл `specs/` и что значат их ошибки. Правила записи файлов — `syntax.md`, сущность по пути — «Сущности» в `rules.md`. Каждый уровень работает на выходе предыдущего. В файле с ошибкой лексики или синтаксиса схема и ссылки не проверяются.

| Уровень | Вход → выход | Правила |
|---|---|---|
| пути | путь файла → сущность и стартовый символ грамматики | «Пути» |
| лексика | строки → токены | «Лексика» |
| синтаксис | токены → дерево: шапка, блоки, разделы, их свойства и тело | «Грамматика», «Ошибки разбора» |
| ссылки | свойства и тело → ссылки | «Поиск ссылок» в `syntax.md` |
| семантика | дерево и ссылки → нарушения схемы и связей | «Реестр», «Схема сущности», «Виды ссылок» в `syntax.md`. Связи — «Обязательные связи» в `rules.md` |

## Пути

Путь файла задаёт сущность — по «Сущностям» в `rules.md` — и стартовый символ грамматики:

| Файлы | Стартовый символ |
|---|---|
| файлы `delta/` фичи, кроме `delta/_project/adr/` | `delta-file` |
| остальные | `file` |

## Лексика

Строка — ровно один токен. Лексер — автомат с двумя режимами: обычным и fence.

В обычном режиме строки таблицы проверяются сверху вниз, токен — первая подошедшая:

| Токен | Строка | Ошибка |
|---|---|---|
| BLANK | пустая или только из пробелов | — |
| FENCE-OPEN | три и больше бэктиков с начала строки, дальше — необязательный язык без бэктиков: `mermaid`. Включает режим fence | — |
| H1, H2, H3 | `# `, `## `, `## ` и заголовок | `####` и глубже, пустой заголовок |
| PROP | `<Имя>: <значение>` | — |
| LINE | любая другая | — |

В режиме fence:

| Токен | Строка |
|---|---|
| FENCE-CLOSE | только бэктики с начала строки, не меньше, чем у FENCE-OPEN. Включает обычный режим |
| LINE | любая другая |

`~~~` — LINE, не fence.

```ebnf
BLANK       = { " " } ;
FENCE-OPEN  = ticks { char - "`" } ;                (* n — число бэктиков *)
FENCE-CLOSE = ticks ;                               (* не меньше n *)
ticks       = "```" { "`" } ;
H1          = "# " text ;
H2          = "## " text ;
H3          = "## " text ;
PROP        = name ": " text ;                      (* тип значения — по «Реестру» *)
name        = upper { letter } { " " letter { letter } } ;
text        = char - " " { char } ;                 (* непустой, до конца строки *)
```

Символы: `upper` — заглавная буква кириллицы или латиницы, `letter` — любая буква кириллицы или латиницы, `char` — любой символ.

## Грамматика

Над токенами. Грамматика LL(1): правило выбирается по следующему токену. Разбор — рекурсивный спуск, функция на нетерминал.

```ebnf
(* стартовые символы — по «Путям» *)
file        = { BLANK } header { block } EOF ;
delta-file  = { BLANK } ( header | block ) { block } EOF ;   (* шапки нет — шапка не меняется *)

header      = H1 props [ BLANK body ] ;             (* шапка *)
block       = H2 props [ BLANK body ] { section } ;  (* блок *)
section     = H3 props [ BLANK body ] ;             (* раздел *)
props       = { PROP } ;                            (* схема — по формату сущности *)
body        = { BLANK | LINE | PROP | fenced } ;    (* PROP в теле — строка текста *)
fenced      = FENCE-OPEN { LINE } FENCE-CLOSE ;     (* код и диаграммы *)
```

## Ошибки разбора

| Где | Токен | Ошибка |
|---|---|---|
| начало файла | EOF | файл пуст |
| начало `file` | не H1 | нет шапки `#` |
| начало `delta-file` | не H1 и не H2 | файл начинается не с `#` или `##` |
| сразу после `props` | LINE, FENCE-OPEN | под заголовком не свойство — отдели текст пустой строкой |
| шапка | H3 | раздел вне блока |
| после первого заголовка | H1 | `#` — только первым заголовком файла |
| `fenced` | EOF | fence не закрыт |

Строка с ошибкой лексики пропускается. После ошибки синтаксиса разбор пропускает токены до следующего заголовка. В выводе — все ошибки файла.

## Модули

Слой — модуль пакета. Каждый работает на выходе предыдущего:

| Модуль | Слой |
|---|---|
| `paths` | пути |
| `lexer` | лексика |
| `syntax` | грамматика и ошибки разбора: рекурсивный спуск, метод на нетерминал |
| `refs` | поиск ссылок |
| `schema`, `semantics`, `form` | схема сущности из «Структуры» формата и проверка по ней |
| `links` | связи между файлами |
| `workspace`, `merge` | `specs/` в памяти, вливание delta в main |
| `commands`, `numbering`, `examples`, `graph`, `cli` | команды |
