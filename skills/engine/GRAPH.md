# Граф SDD

Команда `graph` показывает связи сущностей в браузере. Для людей: скилы её не запускают, файлы она не пишет.

```
python3 <папка скилов>/engine graph [<фича>] [--specs <путь к specs/>] [--port 8765] [--open] [--json]
```

- без `<фича>` — общий режим: весь main и все фичи
- `<фича>` — путь к `spec.md` или папке фичи, `<ID фичи>` или `<номер>`. Страница открывается в общем режиме сразу на этой фиче: `/?feature=<ID фичи>`
- `--json` — напечатать граф и выйти, без сервера. С `<фича>` — граф изменений фичи
- страница перечитывает файлы раз в секунду и перестраивает граф, когда они меняются

## Режимы

| Режим | Что на графе | «Домены» или «Изменения» | «Связи» |
|---|---|---|---|
| общий | блоки main, действующие ADR, фичи из `new/` и `archive/` | «Домены»: домены и их блоки | фичи, требования, контракты, документация |
| фича | спека, задачи `plan`, части `delta/` фичи и блоки main, связанные с ними | «Изменения»: домены и части с ADDED, MODIFIED, REMOVED | спека и задачи, требования, контракты, документация |

Над графом — полоса с переключателем вида по центру и кнопкой «Обозначения» справа.

«Обозначения» — всплывающая панель поверх графа: стрелки и карточки текущего режима, как пользоваться. Закрывается повторным нажатием, кликом мимо или Esc.

Режим фичи — частный случай общего: туда попадают нажатием на фичу или командой `graph <фича>`. Назад — «← весь main» в заголовке страницы. Фича хранится в адресе страницы.

Заголовок страницы:
- «← весь main» — только в режиме фичи
- название фичи или «main: вся система», под ним второй строкой — статус фичи
- справа — «● обновлено <время>» или «сервер недоступен»

## Цвета

Одна таблица на оба режима: полосы карточек, рамки и стрелки.

| Цвет | Режим фичи | Общий режим |
|---|---|---|
| зелёный | добавление | фича в работе добавит блок |
| синий | модификация | фича в работе изменит блок |
| красный | удаление | фича в работе удалит или заменит блок |
| серый | связь с блоком без изменений | закрытая фича — владелец блока. Связи блоков и фич |
| красный пунктир | — | закрытая фича удалила или заменила блок, его в main уже нет |
| серый пунктир | — | закрытая фича меняла блок раньше |

- пунктир — только история закрытых фич: «меняла раньше» и блок, которого в main уже нет. Рамки — по тому же правилу
- в режиме фичи цвет стрелки — операция блока, на который она указывает. Блок не меняется — стрелка серая. Исключение — «заменяет»: заменяемый ADR фича удаляет, стрелка красная
- наконечник стрелки повёрнут по наклону линии
- на странице цвета описаны в «Обозначениях»

## Столбцы

| Столбец | Узлы | Группы | Режим |
|---|---|---|---|
| Фичи | фичи | «в работе» — `new/`, «закрыты» — `archive/` | общий |
| Спека и задачи plan | карточка спеки, задачи `plan` | — | фича |
| Требования | требования | домен | оба |
| Контракты | элементы контрактов | интерфейс | оба |
| Документация и проект | блоки `domain-docs`, `architecture`, `conventions`, `project-doc`, ADR | «поддомен `<домен>/<поддомен>`», «проект» | оба |

При наведении в общем режиме первой группой столбца может стоять «связано с …» — см. «Взаимодействие».

Группы во всех столбцах, кроме «Спеки и задач plan», сворачиваются: заголовок группы — кнопка ▾/▸ с числом карточек. Стрелки к карточкам свёрнутой группы не рисуются. Состояние запоминается отдельно для каждого столбца и группы. Группа «связано с …» не сворачивается.

Столбец «Фичи»:
- под заголовком — строка фильтра: остаются фичи, у которых в ID или названии есть введённый текст
- группы — «в работе» и «закрыты»

## Карточка

Строки:
1. заголовок
2. кружок и тип: сущность, у элемента контракта — `Тип:`
3. операция или состояние: `+ ADDED`, `~ MODIFIED`, `− REMOVED`, «не меняется», статус фичи, «☑ выполнена» или «☐ не выполнена», «удалён из main фичей X», «добавит фича X», «нет в main»
4. только в режиме закрытой фичи, под чертой: что с частью в текущем main

В режиме фичи цвета — всегда цвета delta: что фича сделала тогда. История — только в нижней строке.

| Узел | Как выглядит | Когда виден |
|---|---|---|
| часть `delta/` | полоса цвета операции. REMOVED — название зачёркнуто | режим фичи |
| часть закрытой фичи, которой в main уже нет | цвета delta, как у любой части. Нижняя строка красным: «в текущем main удалён фичей X» или «в текущем main заменён на ADR Y фичей X» | режим закрытой фичи |
| часть закрытой фичи, которую потом изменила другая фича | цвета delta. Нижняя строка: «в текущем main изменён фичей X» | режим закрытой фичи |
| блок main без изменений | серая рамка без цветной полосы | режим фичи: всегда |
| спека | карточка над задачами, отделена чертой с подписью «задачи» | режим фичи |
| узел, на который ведёт ссылка, но которого нет | курсив, «нет в main» | всегда |
| блок, удалённый из main | красная пунктирная рамка, название зачёркнуто. ADR — «заменён ADR Y фичей X» | под курсором фича, которая его касалась, или выбран связанный блок. Если на него ссылаются блоки main — всегда |
| блок, который добавит фича в работе | зелёная рамка | под курсором эта фича |
| блок, который удалит фича в работе | красная рамка | под курсором эта фича |

Кружок перед типом помечает тип документации и элемента контракта. На странице цвета кружков не расшифровываются: тип подписан рядом. Таблица — для справки.

| Столбец | Тип | Цвет |
|---|---|---|
| Документация и проект | `domain-docs` | серый |
| | `architecture` | фиолетовый |
| | `conventions` | пурпурный |
| | `project-doc` | зелёный |
| | `adr` | жёлтый |
| Контракты | операция | фиолетовый |
| | событие | жёлтый |
| | протокол | пурпурный |
| | модель | серый |

Цвета кружков не повторяют цвета операций и проверены на различимость. Тип подписан текстом рядом с кружком, поэтому цвет — не единственный признак.

## Связи

Блоки между собой:

| Связь | От → к | Откуда берётся |
|---|---|---|
| выводит элемент | требование → элемент | `Контракты:` сценария: контракт выводится из требований |
| использует модель | элемент → элемент | `Вход:`, `Выход:`, `Ошибки:`, `Данные:` и ссылки `contract:` в тексте |
| объясняет | блок документации → элемент | `Контракты:` блока |
| держится на ADR | блок документации или проекта → ADR | ссылки `adr:` в тексте |
| заменяет | ADR фичи → ADR | `Заменяет:`, режим фичи |

Задачи, режим фичи:

| Связь | От → к | Откуда берётся |
|---|---|---|
| реализует | задача → требование или элемент | `Реализует:` |
| документация | задача → части файла документации | `Документация:` |

Фичи, общий режим. Связь «фича → блок» берётся из `delta/` фичи и `Источник:` блока в main:

| Связь | Фича | Когда |
|---|---|---|
| добавит | в работе | ADDED-части ещё нет в main |
| меняет | в работе | MODIFIED |
| удалит | в работе | REMOVED |
| заменит | в работе | её ADR с `Заменяет:` заменит действующий ADR |
| владелец | закрыта | она в `Источник:` блока: её версия в main |
| меняла раньше | закрыта | в main уже версия другой фичи |
| удалила | закрыта | удалила блок, его в main нет |
| заменила | закрыта | её ADR с `Заменяет:` заменил старый ADR |
| меняла, позже удалён | закрыта | блок потом удалила или заменила другая фича |
| опирается на | любая | `Основа:` |

ADR не удаляется через REMOVED: его заменяет новый ADR с `Заменяет:`. Граф считает заменённый ADR удалённым блоком, а фичу с новым ADR — той, что его удалила.

## Откуда история

Журнала истории нет. Граф собирает её заново при каждом построении:
1. разбирает `spec`, `plan` и `delta/` всех фич из `new/` и `archive/`
2. строит две карты: «кто удалил» — id блока → фича с REMOVED этого блока, «кто заменил» — `adr:<старый>` → фича и новый ADR по `Заменяет:`
3. берёт текущий main: `Источник:` блока — фича, чья версия лежит сейчас

Блок есть в main — владелец по `Источник:`. Блока нет — автор удаления по картам. Не нашёлся — «блока больше нет».

Где история неточна:

| Случай | Что покажет граф |
|---|---|
| блок удалили, добавили снова и снова удалили | одну фичу из удаливших, не обязательно последнюю |
| блок меняли несколько фич подряд | только последнюю, из `Источник:` |
| блок документации переименовали | старое имя — «блока больше нет» |
| порядок закрытия фич | неизвестен: номер фичи выдаётся при создании, а не при `sync` |

## Взаимодействие

Общий режим. Выбор главнее наведения:
- ничего не выбрано — наведение показывает связи узла под курсором. Связанные блоки поднимаются наверх своих столбцов группой «связано с …», кроме столбца самого узла
- у фичи под курсором появляются блоки, которые она добавит или удалила, и помечаются блоки, которые она удалит
- нажатие на фичу открывает режим фичи
- нажатие на блок выбирает его: на графе остаются только он и связанные с ним, со стрелками. Наведение на другие узлы ничего не меняет
- выбор держится, пока не нажмут этот блок снова, не выберут другой или не нажмут мимо узлов. Esc снимает выбор

Режим фичи:
- при входе спека выбрана сразу: стрелки всей фичи, текст спеки в панели
- без выбора стрелок нет. Наведение ничего не меняет
- нажатие на спеку рисует стрелки всей фичи
- нажатие на задачу рисует путь её изменений: от задачи по направлению связей — что она реализует и документирует, и куда ведут их связи. Остальные узлы скрыты, спека и задачи остаются
- повторное нажатие на спеку или задачу снимает стрелки
- нажатие на карточку другого столбца открывает её в панели. Выбор спеки или задачи остаётся, её карточка обведена. Стрелки открытой карточки среди нарисованных — толще, остальные — бледнее

Адрес страницы — `?feature=<ID фичи>#<вид>/<id узла>`: фича и выбранный узел переживают перезагрузку.

## Панель

- операция или статус, сущность, файл, `Источник:`, у части `delta/` — `Причина:`, у задачи — «Файлы»
- «Связи» — каждая связь фразой со стороны узла: «меняла раньше фича: 007-login-lockout», «выводит элемент: public-api.login». Связи задачи — по операции части: «добавляет: AUTH-010», «изменяет: AUTH-003», «удаляет: Сессии», со стороны части — «изменяет задача: 001». Нажатие на связь выбирает узел
- у спеки — вкладки «Спека» и «План». «План» — если есть `plan.md`
- у спеки — «Нет в main»: части delta фичи, которых в main нет, и почему: «удалила эта фича», «удалила фича X», «заменила фича X на ADR Y», «добавит при sync», «блока больше нет». Берётся из общего графа
- у остальных узлов — «Текст» части. У частей delta — всегда дельта фичи: у REMOVED это заголовок, а причина — в `Причина:` выше. У блоков без изменений — текст из main
- кнопка «← шире» / «→ уже» меняет ширину панели. Выбор запоминается

Текст — Markdown отдельным блоком с рамкой. Ссылки на узлы графа — кнопки. Диаграммы mermaid свёрнуты: «диаграмма mermaid — показать».

## JSON

`/graph.json` — общий граф. `/graph.json?feature=<ID фичи>` и `graph <фича> --json` — граф изменений фичи.

| Поле | Что это |
|---|---|
| `mode` | `main` или `feature` |
| `feature` | `slug`, `title`, `status`, `path`. В общем режиме — `main` и путь к `main/` |
| `nodes` | узлы, поля — ниже |
| `edges` | `from`, `to`, `kind` — вид связи |
| `version`, `page` | отпечатки `specs/` и страницы: по ним страница перестраивает граф и перезагружается |
| `error` | ошибка разбора. Страница показывает её и держит прошлый граф |

Поля узла:

| Поле | Что это |
|---|---|
| `id` | `req:<ID требования>`, `contract:<ID элемента>`, `adr:<ID ADR>`, `doc:<файл>#<блок>`, `head:<файл>`, `task:<номер>`, `feature:<ID фичи>`, `spec:<ID фичи>`, `new:<id блока>` — блок, который добавит фича в работе |
| `label`, `kind`, `column`, `group`, `domain`, `file` | подпись, сущность, столбец, группа в столбце, домен для вида «Домены» или «Изменения», файл от `main/` |
| `action` | ADDED, MODIFIED, REMOVED или нет |
| `type`, `props`, `text` | `Тип:` элемента, свойства, текст части |
| `source`, `reason`, `owner` | у части `delta/`: `Источник:`, `Причина:`, скил-владелец |
| `done`, `files` | у задачи: выполнена ли, пункты верхнего уровня |
| `status` | у фичи и спеки: статус `spec` |
| `plan` | у спеки: текст `plan.md` или `null` |
| `gone` | у фичи: части `delta/` вне main и почему. Текста spec и plan у фичи нет: они приходят со спекой в режиме фичи |
| `missing` | узла, на который ведёт ссылка, нет |
| `removed_block`, `version`, `by` | у удалённого блока: признак, фича, чья версия показана, фича, которая удалила |
| `replaced_with`, `referenced` | у заменённого ADR — новый ADR. На блок ещё ссылаются блоки main |
| `pending`, `by` | у блока, который добавит фича в работе: признак и фича |
| `later_removed`, `later_changed` | режим закрытой фичи: какая фича потом удалила или заменила часть, чья версия части сейчас в main |
