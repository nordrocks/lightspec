# sdd-sync

Результат — main описывает систему с учётом фичи, `adr` фичи перенесены, `spec` в `done`, `feature` в `archive/`.

Пути — от папки скилов, родительской для папки этого скила. Команды — по «Командам» в `rules.md`. Прочитай `rules.md`.

## Запуск

| Аргумент | Что делать |
|---|---|
| `<номер>` или `<ID фичи>` | закрыть эту `feature` |
| нет | `spec` в `implementing` |

## Шаги

1. Закрой фичу: `sync`.
2. Нарушения — покажи пользователю и остановись. Следующий шаг:
   - задачи не отмечены — `sdd-apply`
   - конфликт с main — `sdd-spec`. Покажи текст блока в main с его `Источник:` и текст блока из `delta`
   - остальное — скил, который владеет файлом с нарушением
3. `sync` прервался после записи — запусти его снова. Уже влитые блоки и перенесённые `adr` он пропускает.
4. Выведи в чат «Итог».
